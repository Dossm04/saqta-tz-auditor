# ТЗ: Онбординг продавцов и выплаты по маркетплейсу TauMarket

Версия 0.9 (черновик для согласования) · Владелец: Департамент цифрового бизнеса · Дата: 14.10.2026

## 1. Цели проекта

- Сократить срок подключения продавца (ИП/ТОО) с 5 рабочих дней до 1 рабочего дня.
- Перевести расчёт комиссий и выплат продавцам с ручных Excel-реестров на автоматический процесс.
- Довести долю продавцов, подключённых через самообслуживание, до 80% к концу 2027 года.

## 2. Границы проекта

Входит: онбординг мерчантов (ИП и ТОО), KYB, расчёт и удержание комиссий, график выплат, резерв под возвраты, личный кабинет продавца, API для учётных систем.
Не входит: приём платежей от покупателей (действующий эквайринг), логистика, программа лояльности.

## 3. Роли

- Продавец — ИП или ТОО, зарегистрированные в РК и реализующие товары через маркетплейс.
- Сотрудник поддержки продавцов — консультирует продавца, видит его карточку.
- Финансовый контролёр — формирует реестры выплат, выполняет корректировки.
- Комплаенс-офицер — принимает решение по KYB в спорных случаях.

## 4. Термины

- KYB — проверка юридического лица/ИП, его руководителя и бенефициаров.
- Резерв — часть начисленных продавцу средств, временно удерживаемая для покрытия возвратов и chargeback.
- T+N — выплата на N-й рабочий день после даты подтверждения доставки заказа.

## 5. Функциональные требования

### 5.1 Онбординг и KYB

FR-01. Продавец регистрируется по номеру телефона и e-mail, затем указывает БИН (для ТОО) или ИИН (для ИП).
FR-02. По БИН/ИИН система запрашивает сведения в ГБД ЮЛ через шлюз электронного правительства: наименование, статус, дату регистрации, руководителя, ОКЭД.
FR-03. Если субъект в статусе «ликвидирован», «в процессе ликвидации» или «бездействующий», заявка отклоняется автоматически.
FR-04. Руководитель и бенефициары с долей 25% и более проверяются по перечню лиц, связанных с финансированием терроризма и экстремизма, и по спискам ПДЛ.
FR-05. Если сервис проверки по перечням не ответил за 10 секунд, продавец активируется в обычном режиме, а проверка повторяется ночным пакетом.
FR-06. Продавец подписывает договор оферты ЭЦП НУЦ РК (ключ юридического лица для ТОО, ключ ИП для ИП).
FR-07. До завершения KYB выплаты продавцу не производятся, начисления накапливаются на его балансе.
FR-08. Чтобы не терять продавцов на старте, новый продавец получает выплаты до 500 000 тенге в месяц, пока документы KYB находятся на проверке.
FR-09. Документы и результаты KYB хранятся не менее 5 лет после прекращения деловых отношений с продавцом.

### 5.2 Комиссии и резерв

FR-10. Базовая комиссия маркетплейса — 7% от суммы заказа, включая НДС; для категории «Электроника» — 5%.
FR-11. Пониженные ставки для категорий «Продукты питания» и «Детские товары» — порядок расчёта уточняется позже, после согласования с коммерческим блоком.
FR-12. Комиссия считается в тиынах целочисленно, итог по заказу округляется до 1 тиына по правилу банковского округления.
FR-13. Из каждой выплаты в резерв удерживается 10%, резерв хранится 14 календарных дней с даты доставки заказа.
FR-14. При возврате товара сумма возврата списывается сначала из резерва, затем из будущих начислений продавца.
FR-15. Финансовый контролёр при необходимости может скорректировать сумму к выплате в разумных пределах.

### 5.3 График выплат

FR-16. Выплаты продавцам выполняются ежедневно по схеме T+1 на текущий счёт продавца (IBAN) в любом банке РК.
FR-17. Минимальная сумма выплаты — 1 000 тенге; меньшая сумма переносится на следующий день.
FR-18. Выплата не формируется, если баланс продавца после всех удержаний отрицательный.
FR-19. Продавец может сменить IBAN для выплат в личном кабинете; новые реквизиты применяются сразу, без повторной проверки, чтобы не задерживать ближайшую выплату.
FR-20. Реестр выплат передаётся в АБС банка файлом в формате MT102 один раз в сутки в 18:00.
FR-21. Если АБС вернула ошибку по отдельной выплате, финансовый контролёр отправляет её повторно вручную из реестра.

### 5.4 Личный кабинет продавца

FR-22. Вход в кабинет — по логину и паролю с подтверждением одноразовым кодом из SMS; отключить второй фактор пользователь не может.
FR-23. Кабинет показывает начисления, удержания, резерв, статусы выплат и акты сверки за любой период.
FR-24. Номер счёта в кабинете отображается в маскированном виде: KZ** **** **** **** 1234.
FR-25. Интерфейс кабинета должен быть удобным и интуитивно понятным для продавца.

### 5.5 API для учётных систем

FR-26. Продавцу предоставляется REST API: выгрузка начислений, выплат, возвратов и актов сверки в формате JSON.
FR-27. API-ключ генерируется при активации продавца, действует бессрочно и направляется на e-mail руководителя открытым текстом.
FR-28. О смене статуса выплаты система уведомляет продавца вебхуком на указанный им URL; подпись запросов не требуется, допускается HTTP для упрощения интеграции с 1С.
FR-29. Повторная отправка вебхука — до 5 попыток с экспоненциальной задержкой (1, 2, 4, 8, 16 минут).
FR-30. Готовый модуль обмена для 1С:Бухгалтерия — TBD.

## 6. Нефункциональные требования

NFR-01. Ночной расчёт комиссий по всем заказам за сутки завершается не позднее 06:00 по времени Астаны.
NFR-02. Личный кабинет и API выдерживают 300 запросов в секунду при времени ответа не более 1 с (95-й перцентиль).
NFR-03. Выплата поступает на счёт продавца не позднее 3 рабочих дней с даты доставки заказа.
NFR-04. Средства резерва возвращаются продавцу через 30 дней после доставки, если по заказу не было возврата.
NFR-05. Для ускорения разбора обращений сервис онбординга пишет в лог приложения полный ответ ГБД ЮЛ, ИИН руководителя и реквизиты счёта продавца.
NFR-06. Персональные данные продавцов и бенефициаров хранятся на серверах, расположенных на территории РК.
NFR-07. Тестовый контур работает на обезличенных данных; выгрузка реальных БИН и реквизитов продавцов в тестовую среду запрещена.

## 7. Интеграции

- ГБД ЮЛ / ГБД ФЛ — через шлюз электронного правительства.
- Перечни АФМ и ПДЛ — внутренний сервис комплаенса банка.
- АБС банка — файловый обмен в формате MT102.
- SMS-шлюз — отправка одноразовых кодов.

## 8. Ограничения и допущения

- Выплаты производятся только в тенге.
- Продавцы-нерезиденты на первом этапе не подключаются.

## 9. Этапы

- Этап 1 (декабрь 2026): онбординг и KYB.
- Этап 2 (февраль 2027): комиссии, резерв, выплаты.
- Этап 3: API и интеграция с 1С — сроки определим по итогам этапа 2.
