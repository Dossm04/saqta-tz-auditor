### Цели
Дать клиенту возможность самостоятельно и обратимо приостановить операции по карте, если он временно не может её найти, не обращаясь в контакт-центр и не перевыпуская карту.

### Архитектура решения
Мобильное приложение → API-шлюз → сервис карт → карточный процессинг (смена статуса карты). Сервис карт → сервис уведомлений. Сервис карт → журнал аудита.

### Дизайн процесса UI
Карты → выбранная карта → «Заморозить карту». Открывается шторка с выбором причины и кнопкой «Заморозить». После заморозки на изображении карты появляется значок снежинки, а кнопка меняется на «Разморозить». Разморозка выполняется одним нажатием кнопки «Разморозить».

### Требования к изменениям

#### BPMN схема процесса
Выбор карты → выбор причины → заморозка в процессинге → уведомление клиента → карта в статусе FROZEN → (разморозка клиентом) → карта в статусе ACTIVE.

#### Функциональные требования
* **Ф-1.** Заморозить можно карту в статусе ACTIVE. Заморозка доступна для виртуальных и физических карт.
* **Ф-2.** Заморозка применяется в процессинге не позднее 10 секунд после нажатия кнопки «Заморозить».
* **Ф-3.** При заморозке система меняет статус карты в процессинге, отправляет клиенту push, записывает событие в журнал аудита и предлагает клиенту перевыпустить карту.
* **Ф-4.** Для замороженной карты блокируются расходные операции, кроме —.
* **Ф-5.** Зачисления на замороженную карту по возможности проходят в обычном режиме.
* **Ф-6.** Заморозка действует до тех пор, пока клиент сам не разморозит карту.
* **Ф-7.** Разморозка возвращает карту в статус ACTIVE. Разморозка доступна в любое время суток.
* **Ф-8.** Если карта не разморожена клиентом в течение 30 дней, она автоматически размораживается.
* **Ф-9.** Повторная заморозка уже замороженной карты не меняет её статус и возвращает успешный результат.

### Sequence Diagram
Приложение → сервис карт: заморозить карту. Сервис карт → процессинг: установить статус FROZEN. Процессинг → сервис карт: статус установлен. Сервис карт → сервис уведомлений: push «Карта заморожена». Сервис карт → журнал аудита: событие заморозки. Сервис карт → приложение: результат.

### Нефункциональные требования
* Время смены статуса карты в процессинге — не более 1 минуты.
* Интерфейс заморозки должен быть интуитивно понятным.
* Для анализа инцидентов сервис карт сохраняет в лог тело запроса и ответа целиком вместе с заголовками, включая Authorization.

### Требования к данным
Хранить идентификатор карты, предыдущий и текущий статус, причину заморозки, дату и время заморозки и разморозки, канал (мобильное приложение).

## Часть B. REST API

Дочерний документ части A: «Заморозка карты — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Заморозка карты клиентом |
| **REST type** | PATCH |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | CardStatusController |
| **URL type** | Dev / Prod |
| **Request URL** | `/cards/{pan}/freeze` |
| **CURL** | `curl -X DELETE "$BASE/cards/4400430012345678/freeze" -H "Authorization: Bearer $TOKEN" -d '{"reason":"LOST"}'` |
| **Swagger** | — |
| **Gitlab project** | cards/card-status-service |
| **Developer** | Команда карт |

### Логика работы метода
1. Проверить сессию клиента.
2. Проверить, что карта существует и находится в статусе ACTIVE.
3. Передать в процессинг новый статус карты.
4. Сохранить причину заморозки.
5. Вернуть новый статус карты.

### Особые правила
1. Заморозка не отменяет уже авторизованные, но не списанные операции.
2. Причина заморозки обязательна.

### Параметры запроса

#### Path-параметры

| Parameter | Format | Size | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `pan` | string | 16 | Да | Только цифры | Номер карты |

#### Request body
* **Content-Type:** `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `reason` | string | 1–20 | Да | — | Причина заморозки | `freeze_reason` |

### Ответ

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `status` | string | TEMP_BLOCKED / BLOCKED | Новый статус карты | `card_status` |
| `changedAt` | string | ISO 8601 | Время смены статуса | `status_changed_at` |

### Статусы

**200.** Карта заморожена.  
**409.** Карта уже заморожена.  
**401.** Требуется авторизация.

#### 200. Successful
```json
{"status":"TEMP_BLOCKED","changedAt":"2026-11-20T14:03:11+05:00"}
```

#### 409. Conflict
```json
{"message":"Карта уже заморожена"}
```

#### 401. Unsuccessful — Unauthorized
```json
{"message":"Требуется вход"}
```
