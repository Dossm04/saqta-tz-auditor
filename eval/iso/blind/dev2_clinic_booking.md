# Онлайн-запись к врачу в сети клиник «МедЛайн»

| Поле | Значение |
|---|---|
| Наименование задачи | Онлайн-запись пациентов к врачу через сайт и мобильное приложение |
| Продукт | Портал пациента «МедЛайн» |
| Тип работы | Новая функциональность |
| Задача в JIRA | MED-3127 |
| Заказчик | Дирекция по клиентскому сервису |
| Версия документа | 1.0 (черновик) |

## Часть A. Бизнес-требования

### 1. Описание и бизнес-цель

Сеть «МедЛайн» объединяет 14 клиник в Москве, Екатеринбурге и Новосибирске. Сейчас запись к врачу выполняется только по телефону через колл-центр, что создаёт очереди и потерю обращений. Цель — дать пациентам возможность самостоятельно записываться к врачу онлайн и снизить нагрузку на колл-центр на 40% в течение 6 месяцев после запуска.

### 2. Термины

| Термин | Определение |
|---|---|
| Слот | Интервал времени в расписании врача, доступный для записи |
| Первичный приём | Первое обращение пациента к врачу данной специальности |
| Повторный приём | Обращение к тому же врачу в течение 30 дней после первичного |
| МИС | Медицинская информационная система клиники, источник расписания |
| Лист ожидания | Очередь пациентов, желающих записаться к врачу при отсутствии свободных слотов |

### 3. Роли

| Действие | Пациент | Регистратор | Врач | Администратор клиники |
|---|---|---|---|---|
| Просмотр расписания | + | + | + | + |
| Запись на приём | + | + | – | – |
| Перенос записи | – | + | – | – |
| Отмена записи | + | – | – | + |
| Отметка явки | – | – | + | – |
| Внесение заключения | – | – | + | – |
| Просмотр заключения | + (свои) | – | + | уточняется |

### 4. Функциональные требования

**Ф-1. Просмотр расписания.** Пациент выбирает город, клинику, специальность и врача и видит свободные слоты на 14 календарных дней вперёд.

**Ф-2. Длительность слота.** Стандартная длительность слота — 20 минут. Для первичного приёма бронируются два смежных слота (40 минут).

**Ф-3. Запись.** Пациент выбирает свободный слот, проверяет данные и нажимает «Записаться». После нажатия «Записаться» слот закрепляется за пациентом, и он получает SMS с подтверждением.

**Ф-4. Ограничение активных записей.** Пациент не может иметь более 2 активных записей к одному врачу одновременно.

**Ф-5. Отмена пациентом.** Пациент может отменить запись в личном кабинете не позднее чем за 2 часа до начала приёма. Освободившийся слот становится доступен для записи.

**Ф-6. Напоминания.** Пациенту своевременно отправляется SMS-напоминание о предстоящем приёме.

**Ф-7. Перенос.** Регистратор может перенести запись пациента на другой свободный слот того же врача. Пациент получает SMS о переносе.

**Ф-8. Болезнь врача.** Если врач заболел, регистратор отменяет все записи врача на соответствующие дни. Пациенты получают SMS с предложением записаться к другому врачу.

**Ф-9. Работа врача.** Врач видит список пациентов на день, отмечает явку пациента, вносит заключение по итогам приёма и при необходимости назначает повторный приём.

**Ф-10. Хранение заключений.** Заключения врачей хранятся в портале и доступны пациенту в личном кабинете. Хранение выполняется в соответствии с требованиями законодательства.

**Ф-11. Лист ожидания.** Если у врача нет свободных слотов, пациент может встать в лист ожидания. При освобождении слота пациент получает уведомление и может записаться.

**Ф-12. Неявки.** Если пациент 3 раза подряд не явился на приём без отмены, онлайн-запись для него блокируется.

**Ф-13. Время приёма.** Время приёма отображается пациенту в формате ЧЧ:ММ рядом с датой и адресом клиники.

### 5. Нефункциональные требования

| № | Требование |
|---|---|
| НФ-1 | Интерфейс записи должен быть удобным для пациентов старшего возраста. |
| НФ-2 | Время ответа сервиса поиска слотов — не более 2 секунд. |
| НФ-3 | Персональные и медицинские данные передаются только по TLS 1.2+ и хранятся в зашифрованном виде. |
| НФ-4 | Портал поддерживает до 5 000 одновременно работающих пользователей. |
| НФ-5 | Все действия регистраторов и врачей с записями фиксируются в журнале аудита. |

### 6. Интеграции

| Система | Назначение |
|---|---|
| МИС клиник | Источник расписания врачей и записей; синхронизация расписания выполняется периодически |
| SMS-шлюз | Отправка подтверждений, напоминаний и уведомлений о переносе и отмене |
| ЕСИА / SSO портала | Аутентификация пациента |

### 7. Критерии приемки

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Пациент записывается на свободный слот | Запись создана, пациент получил SMS с подтверждением |
| 2 | Пациент отменяет запись за 1 час до приёма | Запись отменена, слот снова доступен |
| 3 | Пациент пытается создать 4-ю активную запись к тому же врачу | Отказ с сообщением о превышении лимита |
| 4 | У врача нет свободных слотов, пациент встаёт в лист ожидания, затем другой пациент отменяет запись | Пациенту из листа ожидания отправлено уведомление |
| 5 | Регистратор переносит запись пациента | Запись перенесена, пациент получил SMS |
| 6 | Врач вносит заключение | Заключение отображается у пациента в личном кабинете |

## Часть B. Спецификация REST API

Базовый URL: `https://api.medline.ru`. Авторизация — заголовок `Authorization: Bearer <token>`.

### B.1 Поиск свободных слотов

`GET /api/v2/slots`

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| clinicId | integer | да | Идентификатор клиники |
| doctorId | integer | да | Идентификатор врача |
| dateFrom | string (date) | да | Дата начала периода |
| days | integer | нет | Количество дней, от 1 до 30, по умолчанию 30 |

```bash
curl -X GET "https://api.medline.ru/api/v2/slots?clinicId=12&doctorId=541&dateFrom=2026-12-01&days=7" \
  -H "Authorization: Bearer eyJhbGciOi..."
```

Пример ответа (200 OK):

```json
{
  "doctorId": 541,
  "slots": [
    {"slotId": "s-90011", "start": "2026-12-01T10:00:00"},
    {"slotId": "s-90012", "start": "2026-12-01T10:15:00"},
    {"slotId": "s-90013", "start": "2026-12-01T10:30:00"}
  ]
}
```

### B.2 Создание записи

`POST /api/v2/appointments`

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| slotId | string | да | Идентификатор слота |
| patientId | integer | да | Идентификатор пациента |
| visitType | string | да | `primary` или `repeat` |

```bash
curl -X POST "https://api.medline.ru/api/v2/appointments" \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -H "Content-Type: application/json" \
  -d '{"slotId": "s-90011", "patientId": "P-10023", "visitType": "primary"}'
```

Пример успешного ответа (201 Created):

```json
{"appointmentId": "a-55120", "status": "BOOKED", "start": "2026-12-01T10:00:00"}
```

Пример ответа, если слот уже занят (200 OK):

```json
{"success": false, "error": "SLOT_TAKEN"}
```

### B.3 Отмена записи

`PUT /api/v2/appointments/cancel`

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| appointmentId | string | да (query) | Идентификатор записи |
| phone | string | да (query) | Номер телефона пациента для подтверждения |

```bash
curl -X PUT "https://api.medline.ru/api/v2/appointments/cancel?appointmentId=a-55120&phone=%2B79161234567" \
  -H "Authorization: Bearer eyJhbGciOi..."
```

### B.4 Получение заключений пациента

`GET /api/v2/patients/{patientId}/conclusions`

Возвращает все заключения врачей по указанному `patientId`. Доступно любому авторизованному пользователю портала.

Пример ответа (200 OK):

```json
[
  {"conclusionId": "c-881", "doctor": "Иванова А.П.", "date": "2026-11-20", "text": "ОРВИ, назначено лечение..."}
]
```

### B.5 Коды ответов

| Код | Значение |
|---|---|
| 200 | Успешная обработка |
| 201 | Запись создана |
| 400 | Ошибка валидации |
| 500 | Внутренняя ошибка сервера |
