## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | P2P-переводы по номеру телефона с суточным и месячным лимитом |
| **Продукт** | Мобильный банк, розничные клиенты |
| **Бизнес-процесс** | Переводы между физическими лицами |
| **Business owner / Product owner / Аналитик** | Директор по ежедневному банкингу / Владелец продукта «Переводы» / Системный аналитик команды платежей |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, сервис переводов, сервис лимитов, справочник клиентов, сервис уведомлений |
| **Задача в JIRA** | PAY-2417 |

### Цели
Дать клиенту возможность перевести деньги другому физическому лицу по номеру мобильного телефона без ввода реквизитов карты и при этом ограничить риски мошенничества суточным и месячным лимитом.

### Архитектура решения
Мобильное приложение → API-шлюз → сервис переводов. Сервис переводов → справочник клиентов (поиск получателя по телефону) → сервис лимитов → АБС (списание и зачисление) → сервис уведомлений.

### Дизайн процесса UI
Платежи → Переводы → «По номеру телефона». Клиент вводит номер телефона получателя или выбирает его из контактов, затем видит имя получателя, выбирает карту списания, вводит сумму и комментарий (до 140 символов). Под полем суммы отображается доступный остаток суточного лимита. Кнопка «Перевести» активна, если сумма больше нуля. После подтверждения открывается экран результата со статусом перевода.

### Требования к изменениям

#### BPMN схема процесса
Ввод номера телефона → поиск получателя → ввод суммы → проверка лимитов → подтверждение клиентом → списание → зачисление получателю → уведомления → завершение.

#### Функциональные требования
* **Ф-1.** Перевод доступен клиенту с активной дебетовой картой в тенге. Получатель — клиент банка, у которого к номеру телефона привязана активная карта в тенге.
* **Ф-2.** Суточный лимит переводов по номеру телефона составляет 500 000 ₸ на клиента. Лимит считается по сумме успешных переводов за сутки.
* **Ф-3.** Месячный лимит переводов по номеру телефона составляет 3 000 000 ₸ на клиента за календарный месяц.
* **Ф-4.** Комиссия за перевод взимается по тарифам банка и показывается клиенту до подтверждения.
* **Ф-5.** После ввода суммы система проверяет суточный и месячный лимит, показывает получателя, отправляет клиенту SMS с кодом подтверждения, а после списания записывает перевод в историю операций и отправляет push получателю.
* **Ф-6.** Крупный перевод требует дополнительной проверки службой финансового мониторинга до зачисления.
* **Ф-7.** Минимальная сумма перевода — 100 ₸. Сумма указывается в целых тенге.
* **Ф-8.** Лимиты для клиентов премиум-сегмента — заполняется позже.
* **Ф-9.** При превышении любого лимита перевод не выполняется, клиенту показывается сообщение с доступным остатком лимита.

### Sequence Diagram
Приложение → сервис переводов: найти получателя по телефону. Сервис переводов → справочник клиентов: получить ФИО и карту получателя. Сервис переводов → приложение: вернуть ФИО получателя. Приложение → сервис переводов: создать перевод. Сервис переводов → сервис лимитов: проверить и зарезервировать лимит. Сервис переводов → АБС: списать и зачислить. Сервис переводов → сервис уведомлений: push отправителю с суммой, полным номером карты списания и остатком на счёте.

### Нефункциональные требования
* Сервис должен работать быстро и выдерживать высокую нагрузку в праздничные дни.
* Доступность сервиса переводов — 99,9 % в месяц.
* Для разбора инцидентов сервис переводов пишет в лог полный URL каждого запроса.

### Требования к данным
Хранить идентификатор перевода, идентификатор отправителя, номер телефона получателя, сумму в тенге, комиссию, статус перевода, дату и время операции. Для сервиса лимитов хранить накопленную сумму за сутки и за месяц; значение месячного лимита по умолчанию — 5 000 000 ₸.

### Требования к интеграции
Приложение вызывает методы сервиса переводов, описанные в дочернем документе «Переводы по номеру телефона — REST API». Сервис лимитов вызывается синхронно; при недоступности сервиса лимитов перевод не выполняется.

## Часть B. REST API

Дочерний документ части A: «Переводы по номеру телефона — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание перевода по номеру телефона |
| **REST type** | GET |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | P2PTransferController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `/p2p/transfer` . Prod: `/api/v1/p2p/transfer` |
| **CURL** | `curl -G "$BASE/p2p/transfer" -H "Authorization: Bearer $TOKEN" --data 'phone=77011234567&cardId=c-1001&amount=10000&comment=долг'` |
| **Swagger** | — |
| **Gitlab project** | payments/p2p-service |
| **Developer** | Команда платежей |

### Логика работы метода
1. Проверить сессию клиента.
2. Найти получателя по номеру телефона в справочнике клиентов.
3. Проверить суточный и месячный лимит отправителя.
4. Списать сумму с карты `cardId` и зачислить на карту получателя.
5. Вернуть статус перевода.

### Особые правила
1. Номер телефона передаётся в формате 11 цифр без знака «+».
2. Сумма в целых тенге, минимальная сумма 100 ₸, суточный лимит 1 000 000 ₸.
3. Комментарий не более 140 символов.

### Параметры запроса

#### Query-параметры

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 11 | Да | Только цифры | Телефон получателя | `recipient_phone` |
| `cardId` | string | 1–64 | Да | Карта отправителя | Карта списания | `card_id` |
| `amount` | integer | 32 bit | Да | ≥ 100 | Сумма в тенге | `amount_kzt` |
| `comment` | string | 0–140 | Нет | — | Комментарий | `comment` |

#### Request body
Тело не используется.

### Ответ

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `transferId` | string | При успехе | Идентификатор перевода | `transfer_id` |
| `status` | string | SUCCESS / REJECTED | Статус перевода | `status` |
| `amount` | string | — | Сумма перевода | `amount_kzt` |
| `recipientName` | string | Всегда | Полное ФИО получателя | — |
| `limitLeft` | integer | При отказе по лимиту | Остаток суточного лимита | — |

### Статусы

**201.** Перевод создан.  
**422.** Превышен лимит.  
**401.** Требуется авторизация.

#### 200. Successful
```json
{"transferId":"t-88231","status":"SUCCESS","amount":"10000","recipientName":"Сейткалиев Арман Бауыржанович"}
```

#### 400. Limit exceeded
```json
{"status":"REJECTED","limitLeft":12000,"message":"Превышен лимит"}
```

#### 401. Unsuccessful — Unauthorized
```json
{"message":"Требуется вход"}
```
