# Автоплатёж за коммунальные услуги

| Поле | Значение |
|---|---|
| Наименование задачи | Автоматическая ежемесячная оплата коммунальных услуг |
| Продукт | Мобильный и интернет-банк для физических лиц |
| Тип работы | Доработка существующего функционала платежей |
| Задача в JIRA | PAY-5518 |
| Заказчик | Управление платёжных сервисов |
| Версия документа | 0.7 |

## Часть A. Бизнес-требования

### 1. Описание и бизнес-цель

Клиенты оплачивают коммунальные услуги вручную каждый месяц и часто допускают просрочки. Цель — дать клиенту возможность один раз настроить автоплатёж, после чего банк будет ежемесячно оплачивать выставленные поставщиком счета с карты клиента. Целевой показатель — 150 000 активных автоплатежей через год после запуска.

### 2. Термины

| Термин | Определение |
|---|---|
| Поставщик | Организация, оказывающая коммунальные услуги и подключённая к биллингу банка |
| Лицевой счёт | Номер абонента у поставщика |
| Начисление | Сумма к оплате по счёту поставщика за расчётный период |
| Карта списания | Платёжная карта клиента, с которой выполняется автоплатёж |
| Лимит | Максимальная сумма одного списания по автоплатежу |

### 3. Функциональные требования

**Ф-1. Подключение.** Клиент выбирает поставщика из справочника, указывает лицевой счёт, карту списания, день списания (с 1 по 28 число) и лимит. Автоплатёж может подключить только держатель карты списания.

**Ф-2. Сумма списания.** Сумма списания равна сумме начисления по счёту поставщика. Если сумма начисления превышает лимит, списание не выполняется, а клиент получает push-уведомление с предложением оплатить счёт вручную.

**Ф-3. Лимит.** Лимит по умолчанию — 30 000 тенге. Клиент может установить лимит до 150 000 тенге.

**Ф-4. Комиссия.** За каждое успешное списание взимается комиссия 0,5% от суммы начисления, но не менее 50 и не более 500 тенге.

**Ф-5. Недостаточно средств.** Если на карте недостаточно средств, повторная попытка списания выполняется через сутки. Всего выполняется до 3 попыток, после чего автоплатёж за текущий месяц считается неуспешным, и клиент получает уведомление.

**Ф-6. Уведомления.** За 1 день до даты списания клиенту приходит push-уведомление с суммой предстоящего списания. После списания клиент получает push с результатом операции.

**Ф-7. Управление автоплатежом.** Клиент может приостановить и возобновить автоплатёж, изменить лимит и день списания, сменить карту списания и полностью отключить автоплатёж.

**Ф-8. Перевыпуск карты.** Если карта списания перевыпущена или срок её действия истёк, автоплатёж переносится на новую карту при необходимости.

**Ф-9. Время списания.** Списание выполняется в выбранный клиентом день в 09:00.

**Ф-10. Получение начисления.** Начисление по лицевому счёту загружается из биллинга поставщика до дня списания.

**Ф-11. Количество автоплатежей.** Один клиент может подключить не более 10 автоплатежей.

**Ф-12. История.** Клиент видит историю всех списаний по автоплатежу с суммой, комиссией и статусом. Срок хранения истории — TBD.

### 4. Нефункциональные требования

| № | Требование |
|---|---|
| НФ-1 | Пакетная обработка всех автоплатежей дня должна завершаться своевременно. |
| НФ-2 | Время ответа API управления автоплатежами — до 500 мс. |
| НФ-3 | Доступность сервиса — не менее 99,5% в месяц. |
| НФ-4 | Данные карт обрабатываются в соответствии с PCI DSS; полный номер карты не хранится в сервисе автоплатежей. |

### 5. Интеграции

| Система | Назначение |
|---|---|
| Биллинг поставщиков | Получение начислений по лицевым счетам |
| Процессинг карт | Списание средств с карты клиента |
| Сервис уведомлений | Напоминание клиенту за 3 дня до списания и уведомление о результате |
| АБС | Учёт комиссии и проводок |

### 6. Критерии приемки

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Подключение автоплатежа с лимитом 50 000 тенге и днём списания 15 | Автоплатёж создан в статусе «Активен» |
| 2 | Начисление 35 000 тенге при лимите 30 000 тенге | Списано 30 000 тенге, клиенту отправлен push о частичной оплате |
| 3 | На карте недостаточно средств при двух попытках подряд | Автоплатёж переведён в статус «Приостановлен», клиент уведомлён |
| 4 | Клиент отключает автоплатёж | Автоплатёж удалён, списания прекращены |
| 5 | Начисление 12 400 тенге, достаточно средств | Списано 12 400 тенге и комиссия, push с результатом |

## Часть B. Спецификация REST API

Базовый URL: `https://api.bank.kz/payments`. Авторизация — заголовок `Authorization: Bearer <token>`.

### B.1 Создание автоплатежа

`POST /api/v1/autopayments`

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| providerId | string | да | Идентификатор поставщика |
| accountNumber | string | да | Лицевой счёт |
| cardId | string | да | Идентификатор карты списания |
| debitDay | integer | да | День списания, 1–28 |
| limit | number | да | Лимит, не более 100 000 тенге |

```bash
curl -X POST "https://api.bank.kz/payments/api/v1/autopayments?cardNumber=4400430012345678" \
  -H "Authorization: Bearer eyJhbGciOi..." \
  -H "Content-Type: application/json" \
  -d '{"providerId": "ALSECO", "accountNumber": "1002003004", "cardId": "c-3321", "debitDay": "15", "limit": 50000}'
```

Сервис создаёт автоплатёж по переданному `cardId`.

Пример ответа (201 Created):

```json
{"autopaymentId": "ap-7781", "status": "ACTIVE", "nextDebitDate": "2026-12-15"}
```

### B.2 Список автоплатежей клиента

`GET /api/v1/autopayments`

Пример ответа (200 OK):

```json
[{"autopaymentId": "ap-7781", "provider": "ALSECO", "limit": 50000, "status": "ACTIVE"}]
```

### B.3 Изменение автоплатежа

`PATCH /api/v1/autopayments/{autopaymentId}`

Позволяет изменить лимит, день списания или карту. Формат тела аналогичен B.1.

### B.4 Отключение автоплатежа

`GET /api/v1/autopayments/{autopaymentId}/delete`

### B.5 Немедленное исполнение

`POST /api/v1/autopayments/{autopaymentId}/execute`

Выполняет внеочередное списание по текущему начислению. Повторный вызов выполняет списание повторно.

```bash
curl -X POST "https://api.bank.kz/payments/api/v1/autopayments/ap-7781/execute" \
  -H "Authorization: Bearer eyJhbGciOi..."
```

Пример успешного ответа (200 OK):

```json
{"paymentId": "p-120044", "amount": 12400, "commission": 124, "total": 12524, "status": "SUCCESS"}
```

Пример ответа при недостатке средств (200 OK):

```json
{"result": "FAIL", "reason": "INSUFFICIENT_FUNDS"}
```

### B.6 Коды ответов

| Код | Значение |
|---|---|
| 200 | Успешная обработка |
| 201 | Автоплатёж создан |
| 400 | Ошибка валидации |
| 500 | Внутренняя ошибка сервера |
