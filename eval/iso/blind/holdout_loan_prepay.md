## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Частичное досрочное погашение (ЧДП) потребительского кредита в мобильном приложении |
| **Продукт** | Мобильный банк, беззалоговые потребительские кредиты |
| **Бизнес-процесс** | Обслуживание кредита |
| **Business owner / Product owner / Аналитик** | Директор по кредитованию физических лиц / Владелец продукта «Кредиты» / Аналитик кредитного конвейера |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, кредитный модуль АБС, сервис графиков, сервис уведомлений |
| **Задача в JIRA** | LOAN-3310 |

### Цели
Позволить заёмщику без визита в отделение направить часть средств на досрочное погашение кредита и сразу увидеть новый график платежей.

### Архитектура решения
Мобильное приложение → API-шлюз → сервис досрочного погашения → кредитный модуль АБС. Сервис досрочного погашения → сервис графиков (расчёт нового графика). Сервис досрочного погашения → сервис уведомлений (SMS).

### Дизайн процесса UI
Кредиты → выбранный кредит → «Погасить досрочно» → «Частично». Клиент вводит сумму, выбирает счёт списания и вариант: «Сократить срок» или «Уменьшить платёж». Ниже показывается предварительный новый график платежей: дата, сумма платежа, остаток основного долга. Даты в графике отображаются в формате ДД.ММ.ГГГГ. Кнопка «Подтвердить» отправляет заявление.

### Требования к изменениям

#### BPMN схема процесса
Выбор кредита → ввод суммы и варианта → предварительный расчёт графика → подтверждение → регистрация заявления → списание в дату ближайшего платежа → пересчёт графика → уведомление → завершение.

#### Функциональные требования
* **Ф-1.** ЧДП доступно по действующему потребительскому кредиту в тенге. Минимальная сумма ЧДП — 10 000 ₸.
* **Ф-2.** Заявление на ЧДП принимается не позднее чем за 1 рабочий день до даты ближайшего планового платежа. Списание выполняется в дату планового платежа.
* **Ф-3.** Клиент выбирает вариант пересчёта: сокращение срока или уменьшение ежемесячного платежа.
* **Ф-4.** В дату платежа система списывает сумму со счёта, пересчитывает график, отправляет клиенту SMS и формирует новое дополнительное соглашение в PDF.
* **Ф-5.** Сумма ЧДП направляется на погашение в следующем порядке: сначала начисленные проценты, затем —.
* **Ф-6.** Если сумма ЧДП вместе с плановым платежом больше или равна полной задолженности, оформляется полное досрочное погашение.
* **Ф-7.** Значительная сумма досрочного погашения требует звонка менеджера для подтверждения.
* **Ф-8.** Если на счёте недостаточно средств в дату платежа, ЧДП не выполняется, списывается только плановый платёж.
* **Ф-9.** Заявление на ЧДП принимается до конца операционного дня.

### Sequence Diagram
Приложение → сервис ЧДП: предварительный расчёт. Сервис ЧДП → сервис графиков: рассчитать график. Приложение → сервис ЧДП: создать заявление. Сервис ЧДП → АБС: зарегистрировать заявление. В дату платежа АБС → сервис ЧДП: результат списания. Сервис ЧДП → сервис уведомлений: SMS клиенту с номером договора, ИИН, суммой списания и остатком задолженности.

### Нефункциональные требования
* Пересчёт графика должен выполняться без заметных для клиента задержек.
* Сервис ЧДП доступен 24/7, кроме регламентных работ АБС.

### Требования к данным
Хранить идентификатор заявления, идентификатор кредита, сумму ЧДП в тенге, выбранный вариант, дату списания, статус заявления (CREATED, EXECUTED, REJECTED), дату и время создания.

### Требования к интеграции
Приложение вызывает методы из дочернего документа «Частичное досрочное погашение — REST API». Регистрация заявления в АБС выполняется синхронно.

## Часть B. REST API

Дочерний документ части A: «Частичное досрочное погашение — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание заявления на частичное досрочное погашение |
| **REST type** | POST |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | PrepaymentController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `/loans/prepay?iin={iin}` . Prod: — |
| **CURL** | `curl -X POST "$BASE/loans/prepay?iin=900101300123" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"loanId":100245,"amount":5000000,"accountId":"a-77","option":"TERM"}'` |
| **Swagger** | — |
| **Gitlab project** | loans/prepayment-service |
| **Developer** | Команда кредитов |

### Логика работы метода
1. Проверить сессию клиента.
2. Найти кредит по `loanId`.
3. Проверить минимальную сумму и дату подачи заявления.
4. Зарегистрировать заявление в АБС.
5. Вернуть идентификатор заявления и параметры нового графика.

### Особые правила
1. Сумма передаётся в тиынах, минимальная сумма — 500 000 тиын (5 000 ₸).
2. Вариант пересчёта: `TERM` — сокращение срока, `PAYMENT` — уменьшение платежа.

### Параметры запроса

#### Query-параметры

| Parameter | Format | Size | Mandatory | Logic | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `iin` | string | 12 | Да | Только цифры | ИИН клиента |

#### Request body
* **Content-Type:** `application/json`.

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `loanId` | integer | 64 bit | Да | Кредит клиента | Идентификатор кредита | `loan_id` |
| `amount` | integer | 64 bit | Да | ≥ 500 000 | Сумма ЧДП в тиынах | `prepay_amount` |
| `accountId` | string | 1–64 | Да | — | Счёт списания | `account_id` |
| `option` | string | 4–7 | Нет | TERM / PAYMENT | Вариант пересчёта | `recalc_option` |

### Ответ

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `requestId` | string | При успехе | Идентификатор заявления | `request_id` |
| `status` | string | CREATED / REJECTED | Статус заявления | `status` |
| `debitDate` | string | — | Дата списания | `debit_date` |
| `newPayment` | number | При варианте PAYMENT | Новый платёж в тенге | — |

### Статусы

**201.** Заявление создано.  
**400.** Неверные параметры.  
**422.** Недостаточно средств на счёте.

#### 201. Created
```json
{"requestId":"pr-5521","status":"CREATED","debitDate":"2026-12-10","newPayment":41250.00}
```

#### 400. Bad request
```json
{"message":"Сумма меньше минимальной"}
```

#### 200. Insufficient funds
```json
{"status":"REJECTED","message":"Недостаточно средств"}
```
