# Питч и защита: Saqta TZ Auditor

Сценарий на 5 минут + ответы на вопросы жюри. Критерии оценки: вопросы, архитектура, ценность, презентация (по 25%).

## 0. Подготовка (за 10 минут до выступления)

- `streamlit run app.py`, провайдер — «Из .env» (LLM) или «Офлайн-правила» (если нет сети).
- Прогнать демо-ТЗ один раз заранее: ответы LLM попадут в кэш, на сцене анализ будет мгновенным и воспроизводимым.
- Открыть вторую вкладку с README (таблица eval) и `docs/PRIVACY.md`.

## 1. Боль — 30 секунд

> Ревью ТЗ финтех-продукта — это 3–4 часа работы аналитика плюс ИБ-специалиста и комплаенса. Дефекты требований
> находят в разработке или в проде: хранение CVV — нарушение PCI DSS, ПДн в зарубежном облаке — нарушение закона РК,
> «переводы без подтверждения» — прямые потери клиентов. Исправлять на этапе требований в десятки раз дешевле.

## 2. Живое демо — 2 минуты

1. Демо-ТЗ «Мобильный банк» → **Анализировать**. Показать, как агенты загораются по стадиям; три аналитика работают параллельно.
2. Итог **47/100 «Не готово»**, **⏱ 1 с вместо ≈4 ч** ручного ревью.
3. Находка **«Хранение CVV»**: дословная цитата, строка L35, норма PCI DSS v4.0.1, готовая формулировка исправления.
4. Находка-противоречие **L43 «до 50 000 ₸ без подтверждения» vs L44 «каждая операция подтверждается»** — смысловое, не по ключевым словам.
5. Вкладка **«Повестка встречи»**: вопросы сгруппированы по адресатам (ИБ, Комплаенс, Бизнес), у каждого — цитата из ТЗ,
   «зачем», «если не ответить», 2–3 варианта ответа под практику РК и допущение по умолчанию. «≈ N минут встречи».
6. **«Принять рекомендуемые ответы»** → **«Сформировать ТЗ v2 и перепроверить»** → экран **До / После**: балл 47 → 76,
   критичных 10 → 0 (важные замечания остаются автору), список закрытых замечаний.
7. **Экспорт в Word** — отчёт и повестка, которые аналитик отправляет заказчику.

## 3. Архитектура — 1 минута

- 7 агентов с узкими ролями: Reader → (Completeness ‖ Consistency ‖ FinTech/Security) → Verifier → Question Generator → Scorer.
- Вкладка «Агенты и архитектура»: **граф реального запуска** с сообщениями между агентами.
- **Verifier (Critic)** — защита от галлюцинаций: каждая цитата ищется в тексте ТЗ, неподтверждённые находки отсекаются;
  в LLM-режиме отклонённые находки возвращаются агенту на одну ревизию (critic loop).
- **Гибрид LLM + правила**: правила дают LLM подсказки и проверяют его ответы; при сбое провайдера агент перебирает
  резервные модели, затем откатывается на правила — демо не падает.
- **Оценка — формула, а не мнение LLM**: балл нельзя «уговорить» текстом внутри ТЗ.

## 4. Ценность и доказательства — 1 минута

- **Измеренное качество**: `scripts/eval.py` — dev-набор из 7 ТЗ (мобильный банк, кредитование/BNPL, эквайринг, кошелёк,
  депозиты, международные переводы, маркетплейс): найдено **116/116** размеченных дефектов, **0** ложных срабатываний.
  **Слепая отложенная выборка v2** (кредитные карты, Open Banking API, зарплатный проект), написанная без доступа к правилам:
  офлайн-правила находят **24/48 (50%)** при **0** ложных срабатываний. Подробности — README и docs/EVAL.md.
- **Экспертиза РК в базе знаний**: 39 контролей (АРРФР №53/2026, ПОД/ФТ и АФМ, закон о ПДн и локализация, закон о платежах и
  Антифрод-центр НБРК, период охлаждения по онлайн-займам, ЦОИД, банковская тайна), 29 типов опасных требований.
- **Проверка по шаблону** организаторов/банка: загрузили шаблон — система проверит, все ли разделы на месте и заполнены ли поля.
- **Приватность для банка**: локальная модель (Ollama) — данные не покидают контур; для облака — маскирование ИИН, карт, телефонов.

## 5. Ответы на вопросы жюри

| Вопрос | Ответ |
|---|---|
| Чем это лучше одного промпта к ChatGPT? | Узкие роли + проверяемый вывод: каждая находка с цитатой и строкой, Verifier отсекает выдумки, оценка детерминирована, работает офлайн. Один промпт не гарантирует ни полноты контролей РК, ни воспроизводимости. |
| Как вы боретесь с галлюцинациями? | Заземление цитат (нечёткий поиск по тексту), отсев неподтверждённых, перепроверка «отсутствия» правилами, critic loop, белый список норм (без выдуманных номеров статей). Статистика Verifier видна в UI. |
| А если LLM недоступен? | Резервные модели → откат на правила. Офлайн-режим даёт полный отчёт на базе знаний. |
| Можно ли отправлять ТЗ банка во внешний LLM? | Не нужно: пресет «Локальная модель» (Ollama/vLLM в контуре). Для облака — маскирование ПДн (privacy.py), см. docs/PRIVACY.md. |
| Насколько точны ссылки на законы? | Сверены с первоисточниками (adilet, АРРФР, НБРК) на ноябрь 2026; в отчёте дисклеймер — сверять редакцию перед официальным заключением. |
| Как адаптировать под шаблон организаторов? | Загрузить шаблон в блоке «📐 Шаблон ТЗ» над кнопкой «Анализировать» — разделы извлекаются автоматически. |
| Как измеряли качество? | Golden-labels: дефекты с номерами строк + строки, которые нельзя флагать; recall и ложные срабатывания, плюс слепая отложенная выборка. CI прогоняет eval на каждый push. |
| Как это встроить в работу аналитика? | Word-отчёт и повестка встречи, ТЗ v2 с исправлениями, JSON для интеграций, CLI для пайплайнов. |
| Почему оценке можно доверять? | Формула открыта (README): штрафы по серьёзности × уверенность, покрытие контролей. Одинаковое ТЗ → одинаковый балл. |
